# Retroconsole: Dedicated Game Boy Appliance on Legacy Hardware

An Operating Systems university course project that transforms a legacy PC into a dedicated retro gaming appliance. Instead of building an emulator from scratch, the focus is on engineering and measuring the underlying OS subsystems: a custom-compiled Linux kernel, a lightweight C-based init system (PID 1), a minimal graphics stack, and rigorous kernel performance profiling.

## Hardware Specifications

| Component | Detail |
|---|---|
| Motherboard | Biostar H61MH (Micro-ATX, legacy BIOS) |
| CPU | Intel Core i3-2100 (2 cores, 4 threads @ 3.10 GHz) |
| RAM | 4 GB DDR3 |
| Disk | 500 GB Mechanical HDD |
| Input | Wired USB Gamepad |

## Architecture & System Layers (Bottom to Up)

When the machine boots, the system executes the following stack:

| Layer | Component | Description / Responsibility | Status |
|---|---|---|---|
| **1** | **BIOS** | Hardware initialization and boot device lookup. | Firmware |
| **2** | **GRUB** | Bootloader that loads the Linux kernel into memory. | Existing (Debian) |
| **3** | **Linux Kernel** | Manages CPU, memory, disk, and hardware drivers. | **Custom recompiled & trimmed** |
| **4** | **Init (PID 1)** | First user-space process; initializes mounts and manages lifecycle. | **Custom written in C** |
| **5** | **Graphics Server (X)** | Provides the X11 window display context. | Existing (X.Org) |
| **6** | **RetroArch** | Frontend managing windowing, audio, video, and input polling. | Existing |
| **7** | **mGBA Core** | libretro backend emulating Game Boy CPU and PPU cycles. | Existing |
| **8** | **ROM** | Game Boy cartridge binary (`.gb`). | Homebrew / Test ROM |

## Core Components Built by the Team

### 1. Trimmed Custom Kernel
* **Optimization:** Derived from the Debian `.config`, stripping unused hardware modules (Bluetooth, Wi-Fi, RAID/LVM, USB audio, CIFS, NFS) to minimize memory footprint and boot time.
* **Scheduling:** Enabled `CONFIG_PREEMPT` to improve responsiveness under load.

### 2. Custom C Init (PID 1)
Replacing `systemd`, our lightweight PID 1 written in C performs the following lifecycle duties:
1. Mounts essential virtual filesystems (`/proc`, `/sys`, `/dev`).
2. Spawns the graphics server and RetroArch using `fork()` and `exec()`.
3. Monitors processes via `waitpid()`, automatically respawning RetroArch if it crashes and reaping orphaned child processes.
4. Handles system power-off and reboot commands.

### 3. Emulation Stack
RetroArch interacts with the mGBA core via the standard `libretro` API (`retro_run`), executing CPU instruction decoding and PPU video frame rendering at ~60 FPS while keeping CPU overhead minimal on the i3-2100.

## Subsystem Measurements & Benchmarks

The project evaluates four key OS performance domains:
* **CPU Scheduling:** Testing real-time scheduling policies (`SCHED_FIFO` vs. standard) under background CPU pressure generated by `stress-ng`.
* **Memory Management:** Profiling virtual memory allocation, page faults, and kernel behavior under low-memory conditions (OOM killer triggers).
* **Disk I/O:** Benchmarking mechanical hard disk performance comparing `bfq` and `mq-deadline` I/O schedulers using `fio`.
* **Interrupts & Input:** Tracing input latency from USB gamepad hardware interrupts through `/dev/input/eventX` to RetroArch polling.
